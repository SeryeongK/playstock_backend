## 1. 설계 (Why & What)

### 목적
크리에이터가 자신의 유튜브 채널을 플랫폼에 등록하고 조각 판매 조건(총 발행량·가격·기간·배당율)을 설정한다. YouTube Data API로 채널명·썸네일·구독자수를 자동 수집하여 크리에이터가 직접 입력하는 항목을 최소화한다.

### 입력 / 출력
- 입력: `youtubeChannelId`, 카테고리, 총 발행량, 조각 단가, 권리 기간(개월), 배당율
- 출력: 201 Created + 저장된 채널 정보 (채널명·썸네일·상태 포함)

### 핵심 흐름
1. JWT 인증 통과 → `creatorId(Long)` 추출
2. `youtubeChannelId` 중복 체크 → YouTube Data API 호출하여 채널명·썸네일·구독자수 파싱
3. `Channel` 엔티티 생성 (status=PENDING, soldShares=0, reservedShares=0) → 저장 → 201

### 주요 결정
- `ChannelTier`를 BRONZE/SILVER/GOLD 대신 A/B/C로 단순화. AI 가치평가(F005) 구현 전까지 tier는 nullable로 유지.
- YouTube API 호출에 RestClient(Spring 6.1+) 사용. WebClient 대신 선택한 이유: 동기 호출로 충분하고 의존성이 가벼움.
- 채널 최초 등록 상태는 PENDING. ACTIVE 전환은 향후 AI 심사(F005) 통과 후.

## 2. 구현 (How)

### 패키지
`com.playstock.channel`, `com.playstock.infra.youtube`

### 파일 목록
- `channel/Channel.java` — 엔티티. `@PrePersist`로 status=PENDING, sold/reservedShares=0 초기화.
- `channel/ChannelStatus.java` — PENDING / ACTIVE / SOLD_OUT / EXPIRED / SUSPENDED
- `channel/ChannelCategory.java` — FINANCE / TECH / LIFESTYLE / ENTERTAINMENT
- `channel/ChannelTier.java` — A / B / C
- `channel/ChannelRepository.java` — `existsByYoutubeChannelId`
- `channel/ChannelRegisterRequest.java` — Bean Validation 포함 (dividendRate: 0.01~1.00)
- `channel/ChannelRegisterResponse.java` — `Response.from(entity)` 정적 팩토리
- `channel/ChannelRegisterService.java` — 중복 체크 + YouTube API 호출 + 저장
- `channel/ChannelController.java` — POST /channels
- `infra/youtube/YouTubeClient.java` — RestClient 기반. 응답 파싱용 내부 레코드 선언.
- `infra/youtube/YouTubeChannelInfo.java` — channelId, name, thumbnailUrl, subscriberCount

### API
| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/channels` | Bearer JWT | 채널 등록. 201 + 채널 정보 반환 |

### DB 변경
`channels` 테이블 사용 (V1__init_schema.sql에서 이미 생성). 이 기능에서 추가 마이그레이션 없음.

### 의존성
- 선행 기능: F003 (JWT 인증 — creatorId 추출)
- 외부 API: YouTube Data API v3 (`/channels?part=snippet,statistics`)
- 라이브러리: Spring Web (RestClient), Jackson (`@JsonIgnoreProperties`)

### 핵심 코드 (스니펫)
```java
// YouTubeClient — RestClient로 채널 정보 수집 후 레코드로 파싱
ChannelListResponse response = restClient.get()
    .uri("/channels?part=snippet,statistics&id={id}&key={key}", channelId, apiKey)
    .retrieve()
    .body(ChannelListResponse.class);
```

## 4. 후속 (Follow-up)

### 알려진 한계
- 등록 직후 상태가 PENDING이어서 투자자에게 노출되지 않음. ACTIVE 전환 트리거(AI 심사)가 없는 상태.
- YouTube Analytics API (실제 수익/CPM) 미연동 — 현재는 공개 API(구독자수만) 수집.
- `creator_id`로 User 엔티티를 조회할 때 `@ManyToOne(LAZY)` N+1 가능성 있음 (채널 목록 조회 구현 시 주의).

### 미해결
- 채널 목록 조회 API 미구현 (GET /channels). 투자자용 리스트가 필요함.
- ACTIVE 전환 API 또는 AI 심사 연동 미구현 → F005(AI 가치평가)에서 처리 예정.

### 학습 포인트
- [@ManyToOne, FetchType.LAZY, N+1 문제](../learning-notes/jpa.md)
- [JpaRepository 쿼리 메서드 이름 규칙](../learning-notes/jpa.md)

### 향후 개선
- GET /channels — 투자자용 채널 목록 (status=ACTIVE 필터)
- GET /channels/{id} — 채널 상세 (AI 평가 + 사기 탐지 결과 포함)
- AI 심사(F005) 통과 시 PENDING → ACTIVE 자동 전환
