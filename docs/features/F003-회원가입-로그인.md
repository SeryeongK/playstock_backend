## 1. 설계 (Why & What)

### 목적
투자자·크리에이터가 서비스에 접근하기 위한 최소 인증 기반. 이후 모든 API가 JWT Bearer 토큰 인증에 의존하므로 선행 필수 기능.

### 입력 / 출력
- 회원가입 입력: email, nickname, password, role (INVESTOR / CREATOR)
- 회원가입 출력: id, email, nickname, role, createdAt
- 로그인 입력: email, password
- 로그인 출력: accessToken (JWT), email, nickname, role

### 핵심 흐름
1. 회원가입: 이메일 중복 확인 → 비밀번호 BCrypt 해시 → users 테이블 저장
2. 로그인: 이메일로 유저 조회 → 비밀번호 검증 → JWT 발급
3. 이후 요청: JwtAuthenticationFilter가 Bearer 토큰 파싱 → SecurityContext 등록

### 주요 결정
- JWT 단일 토큰 (Refresh Token 없음) — MVP 기간 내 복잡도 축소
- role 단일 컬럼 (INVESTOR / CREATOR / ADMIN) — 추후 권한 플래그 확장 예정

## 2. 구현 (How)

### 패키지
`com.playstock.user`

### 파일 목록
- `user/AuthController.java` — 회원가입·로그인 엔드포인트
- `user/UserController.java` — 내 정보 조회 엔드포인트
- `user/SignupService.java` — 회원가입 유스케이스
- `user/LoginService.java` — 로그인 + JWT 발급 유스케이스
- `user/User.java` — 유저 엔티티
- `user/UserRepository.java` — JPA 레포지토리
- `user/SignupRequest.java`, `SignupResponse.java` — 회원가입 DTO
- `user/LoginRequest.java`, `LoginResponse.java` — 로그인 DTO
- `user/UserResponse.java` — 내 정보 DTO
- `user/UserRole.java` — role enum
- `common/JwtUtil.java` — JWT 생성·파싱 유틸
- `common/JwtAuthenticationFilter.java` — 요청마다 토큰 검증 필터
- `common/config/SecurityConfig.java` — Spring Security 설정

### API
| Method | Path | Description |
|--------|------|-------------|
| POST | `/auth/signup` | 회원가입 |
| POST | `/auth/login` | 로그인 (JWT 발급) |
| GET | `/users/me` | 내 정보 조회 (인증 필요) |

### DB 변경
`V1__init_users.sql` — users 테이블 생성 (id, email, nickname, password_hash, role, point_balance, created_at)

### 의존성
- 선행 기능: F001 (Spring Boot 셋업), F002 (Flyway)
- 라이브러리: Spring Security, jjwt (JWT), BCrypt

### 핵심 코드 (스니펫)
```java
// LoginService.java
String token = jwtUtil.generateToken(user.getId(), user.getRole());
return LoginResponse.of(token, user);
```
